## North star

Turn `./scaffold`'s git-history miner — currently hardcoded for Coq/fiat-crypto —
into a **repo-agnostic agent** that detects a repo's conventions on the fly. See
`CLAUDE.md` and `docs/SoW.md` for the grant-level framing (HuggingFace evals for

## Architecture decision (locked)

**Two-tier: "agent calibrates → profile → deterministic engine executes."**
- **Tier 1 (agentic, once per repo):** a pydantic-ai agent explores a repo + samples
  its git history and emits a **`RepoProfile`** (the regexes/globs/keyword-banks/tactic
  vocab that used to be hardcoded, now *data*). Built on **`pydantic-ai-harness`'s
  `CodeMode`** capability.
- **Tier 2 (deterministic, full history):** the existing `git_walker`/`pattern_detector`,
  now parameterised by a `RepoProfile`. No LLM in the hot loop → fast, reproducible,
  auditable. **This tier is DONE (Phase 1).**

Why not LLM-per-commit: seL4 has 1M+ lines / huge history; per-commit LLM calls are
cost-prohibitive, slow, non-reproducible — bad for a published eval dataset.

User decisions (do not relitigate):
- "Synthesized miner" = **declarative profile (data), not generated Python.** Codegen is a
  deferred stretch goal.
- First proving ground = **fiat-crypto reproduce** (regenerate its golden profile from the
  repo alone).
- Single reference dataset = **`artifacts/fiat-crypto-eval/init-draft/`** (no separate
  regression baseline).
- Back-compat is NOT a concern — full rips are sanctioned.

## The `RepoProfile` contract (`scaffold/src/scaffold/profile.py`)

Fields (all that the engine consumes): `proof_assistant: str`, `proof_file_globs: list[str]`,
`exclude_globs`, `build_files`/`build_commands`, `hole_markers: list[HoleMarker{regex,kind}]`,
`declaration_patterns: list[str]` (group 1 = decl name), `commit_signals: dict[class_name → [regex]]`,
`proof_context_regex`, `classification_priority` (recorded, not yet load-bearing),
`tactic_vocabulary: list[str]`, `tactic_groups: dict[tactic → group]`,
`proof_style_signals: dict[name → regex]` (`term_mode`/`ssreflect`; `tactic_mode`/`mixed` derived),
`structural_terms`, `domain_terms`, `notes`, `provenance`.

`profile.compiled()` → `CompiledProfile` with all regexes pre-compiled (hole_res, declaration_res,
commit_signal_res, proof_context_re, tactic_re [boundary-aware, longest-first], proof_style_res,
keyword_re). The engine always works off `CompiledProfile`. The agent emits a **dict/JSON** (it can't
build pydantic objects inside the Monty sandbox); `RepoProfile.model_validate` turns it into the artifact.

## PHASE 2 PLAN — the CodeMode calibration agent

**Goal:** `scaffold profile <repo> -o artifacts/<repo>-eval/profile.json` — an agent that explores a
repo + samples its git history and emits a `RepoProfile`. **Win condition: regenerate fiat-crypto's
golden profile from the repo alone**, i.e. the agent-produced profile drives the engine to land the
mined challenge set + class distribution within tolerance of `init-draft` (ideally byte-identical on
challenges; class-distribution close on the stratification side).

**Build it on `pydantic-ai-harness` `CodeMode`** (user directive). Layout — mirror the existing
`experiments/agent/` house style:
```
scaffold/src/scaffold/profiler/
  __init__.py
  agent.py     # Agent(model, capabilities=[CodeMode(), ...], output_type=RepoProfile); logfire wired
  tools.py     # @agent.tool_plain host functions (see below)
  deps.py      # ProfilerDeps (repo_path, sample budgets, log) if needed
  prompts.py   # system prompt: how to calibrate + self-validate
```
Add a `profile` command to `cli.py`.

**Tools** (plain `@agent.tool_plain` host functions — they run host-side with full subprocess access;
the agent calls them from sandboxed Python via CodeMode):
- `list_files(glob)`, `read_file(path, start, end)`
- `git_log(n, grep)`, `git_show(sha, path)`, `git_diff(sha)`, `sample_commits(filter, n)`
- `count_regex(pattern, scope)` — fast calibration
- **keystone `test_profile(profile_json, n)`** — validate a candidate `RepoProfile` by running the
  Phase-1 engine (already importable: `ProfileAnalyzer`, `mine_commit`, `dump_commits`,
  `enrich_record`, `enrich_record_with_diff`, `assign_tactic_groups`) over `n` sampled commits and
  returning class distribution + example challenges + raw diffs so the agent self-corrects. This
  feedback loop is what makes it "detect patterns on the fly" rather than one-shot guessing.

**Output:** `output_type=RepoProfile`. Budget via core `UsageLimits` (not the unreleased harness
shield/budget packages).

**Then Phase 3:** run the finished agent on CompCert (Coq, different conventions) and seL4/l4v
(Isabelle — exercises the non-Coq path). These are independent → good place for parallel subagents.
The hardest sub-problem: `spec_change` vs `proof_change` (statement vs body) — may need tree-sitter or
a sampled per-commit LLM adjudication pass. A reliable `declaration → proof body` boundary in the
profile is also the prerequisite for the SoW "ablation slider".

## CodeMode / harness facts (verified, don't re-derive)

- `pydantic-ai-harness` is the new `Agent(model, capabilities=[...])` library. It's **Alpha; the ONLY
  shipped capability is `CodeMode`.** Everything else in its matrix (FileSystem, Shell, SubAgents,
  budgets, guardrails, memory) is unreleased PRs — **do NOT design around them.** Use CodeMode + core
  `pydantic_ai.capabilities` (ToolSearch/Thinking) + core `UsageLimits`.
- **Execution model (the load-bearing fact):** model-written code runs in the **Monty sandbox**
  (restricted: stdlib only — `sys, typing, asyncio, math, json, re, datetime, os, pathlib`; **no
  subprocess, no `import` of third-party, no class definitions, no wall-clock/`time`/`datetime.now`**).
  But **tool callables dispatch HOST-side** and marshal results back. So our git/engine tools run for
  real on the host; the agent orchestrates them from sandboxed Python (loops, regex via `re`,
  aggregation) in 1–2 `run_code` round-trips. REPL state persists across `run_code` calls in a run.
- Usage: `from pydantic_ai_harness import CodeMode`; `Agent('anthropic:claude-…', capabilities=[CodeMode()])`;
  register tools with `@agent.tool_plain`. Selective sandboxing: `CodeMode(tools=[...])` keeps some
  tools native. CodeMode collapses N tool calls into one model round-trip.
- **Hedge:** tools are plain functions, so dropping `CodeMode` falls back to ordinary tool-calling with
  zero rewrites if the alpha lib is rough.

## House style for pydantic-ai in this repo
- `scaffold/src/quali/study.py` — simple output-only agent: `Agent(model, output_type=Schema, system_prompt=…)`,
  `await agent.run(prompt)`, read `result.output`.
- `experiments/agent/` (`agent.py`/`tools.py`/`deps.py`/`runner.py`) — full deps+tools agent:
  `Agent(model_obj, deps_type=Deps, output_type=Verdict, system_prompt=…)`, `@agent.tool` with
  `ctx: RunContext[Deps]`, `agent.run_sync(prompt, deps=…, usage_limits=UsageLimits(request_limit=N))`.
  For `anthropic:` models it wraps in `AnthropicModel` with `AsyncAnthropic(max_retries=8)`.
- Model strings: bare `"anthropic:claude-…"`. API key via `ANTHROPIC_API_KEY` env. quali has a custom
  `.env` loader `load_env()`.

## Gotchas
- **pydantic-ai eagerly constructs the provider at `Agent(...)` time** → needs `ANTHROPIC_API_KEY` set
  (or it raises `UserError`). In bare import/wiring tests, set a dummy key.
- LSP/pyright shows false "Import pydantic/typer/pytest could not be resolved" — interpreter mismatch;
  it runs fine under `uv run`.
- Model can't construct `RepoProfile` in-sandbox (no class defs) → it passes a JSON dict to a host tool
  that validates it; `output_type=RepoProfile` stays the native final emission.
- The golden `profile.json` was built by a one-shot script that lived in the (now-gone) job dir — the
  committed `profile.json` is the artifact of record; the script isn't needed.
